Three privacy risks hiding in files you already send

  • The GPS tag is your home address. A phone photo carries the exact coordinates where it was taken. Post it, and anyone can read where you live, where your kids go to school, where the listing photos were shot.
  • The thumbnail remembers what you cropped out. Cropping a photo does not always remove the original — an embedded EXIF thumbnail can still carry the uncropped image. MetaScrub strips the whole EXIF block, thumbnail included.
  • The revision history tells the story you deleted. A Word file can carry its author, your company, how many revisions it went through, and the fingerprints of every editing session. Sending the "final" version can still hand over the draft history.

The report is the product — find, remove, verify zero

Other metadata cleaners finish with a bare list of "successful" files — no detail about what was actually removed. MetaScrub gives you a per-file triple instead:

  1. Found — every hidden item named: GPS coordinates, BodySerialNumber, author, company, revision traces, XMP metadata, and more.
  2. Removed — what the scrub took out of the cleaned copy.
  3. Rechecked zero — the cleaned copy is audited again, and the report must read 0 target items remaining. If it does not, you see it.

And the content itself is verified untouched: photo pixels are hash-checked, document and PDF text are hash-checked, and every cleaned file is verified to still open.

Honest limits: v1 covers JPEG photos, Office files (docx/xlsx/pptx) and PDFs. PNG, HEIC, TIFF, RAW, video and audio metadata are not scrubbed in this version and are reported as unsupported, never force-converted. Digitally signed PDFs are detected by signature flags and/or a signature-field marker in the file and skipped, never scrubbed, because changing the file would break the signature; detection is marker detection only, not a cryptographic validation of the signature. A scrubbed file is not certified or compliant with any law, standard or platform policy, and scrubbing does not remove tracked-change content itself — only the rsid revision-trace attributes. The report lists exactly what was found and removed; read it before sending anything sensitive.
